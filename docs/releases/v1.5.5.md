# v1.5.5 - 认证请求噪音治理与登录态预检

发布日期：2026-10-16

## Highlights

- 未登录时鉴权请求不再发到后端换取 401：本地既无访问令牌也无刷新令牌时直接静默失败，访客进入管理页不再出现成片「认证失败」。
- 并发 401 只登出一次、只派发一次失效事件、只提示一次；冷却窗口内的后续 401 不再重复提示。
- 进入管理页时同一应用接口不再查询两次（`limit=100` 与 `limit=1000`），技术栈选项直接基于已加载列表分析。
- 受保护页面放行前后端确认会话是否有效：已被撤销的会话会清理本地残留凭证并跳回门户首页；网络异常时放行，不会把已登录用户锁在门外。

## Added

- 请求选项 `suppressAuthHandling`（`main-portal/src/services/api.ts`）：为 `true` 时 401/403 不触发全局登出、认证失效事件与提示，由调用方自行接管。路由守卫的会话预检使用该选项，避免与守卫自身的跳转相互叠加。
- 统一导出 `isAuthError(error)`：401/403 判定，供页面区分「认证类失败」与其它错误，避免同一次失败被页面和 API 层各报一次。
- 前端回归测试 `main-portal/src/tests/api-auth-noise-guard.test.ts`（3 项）：访客态不发请求且不登出不提示、并发 401 只处理一次、冷却窗内不重复处理。
- 前端回归测试 `main-portal/src/tests/route-guards-session-verify.test.ts`（7 项）：无令牌按未登录处理、后端拒绝按会话失效处理、有效会话在窗口期内复用确认结果、网络异常放行、以及 `checkAllPermissions` 的拦截与清理行为。

## Changed

- 鉴权请求前置短路（`services/api.ts`）：`requireAuth` 请求在本地既无访问令牌也无刷新令牌时不再发出，以 `AUTH_REQUIRED` 静默失败；是否跳转登录页交由路由守卫决定。
- 认证失效去重（`services/api.ts`）：新增在途标记与 2 秒冷却窗口，并发 401 只执行一次 `logout(false, false)`、一次 `dispatchAuthInvalidation` 与一次「登录已过期」提示，其余请求照常抛出错误。
- 管理页加载（`views/Management.vue`）：`onMounted` 改为串行的 `initializeAppData()`（`loadApps()` → `loadTechStacks()`）；`loadTechStacks()` 删除自身的 `getApps({ limit: 1000 })` 兜底请求，改为分析本地 `apps.value`；未登录时不建立 WebSocket 连接；三处 catch 对认证类失败保持静默。
- 受保护路由会话预检（`utils/routeGuards.ts`）：`checkAllPermissions` 在本地令牌检查之后调用 `checkServerSession()`，请求 `GET /api/v2/auth/verify`（`suppressAuthHandling` + `showErrorMessage: false` + 8 秒超时）；同一凭证 30 秒内只确认一次；401/403 判定为 `session_invalid`，清掉本地残留会话并跳转 `/portal`；网络异常等无法确认的情况放行。失败文案新增「登录状态已失效，请重新登录」。
- 将根项目、前端、后端、系统配置、锁文件和前端内置更新记录版本统一提升到 `1.5.5`。

## Fixed

- 修复未登录时页面鉴权请求仍会发到后端、每个接口各换回一个 401 的问题（访客进入管理页的成片「认证失败」）。
- 修复并发 401 导致重复登出、重复派发认证失效事件、重复弹出「登录已过期」的问题。
- 修复本地残留会话已被后端撤销（服务重启、会话过期、令牌轮换）时守卫仍放行、用户进入受保护页面后才吃到一串 401 的问题。
- 修复进入管理页时同一应用接口被查询两次、失败信息被报两层的问题。

## Compatibility

- 无后端接口变更；本次为纯前端改动，API 服务无需重启。
- 行为变化：未登录时管理页相关请求不再出现在浏览器 Network 面板（本地短路）；页面不再显示重复错误提示。
- 受保护页面切换时新增一次会话确认请求：同一凭证 30 秒内最多一次，超时 8 秒；后端不可达时按放行处理，真正的认证失效仍由 API 层 401 兜底。
- `dist/` 不入库：本机已重新构建 `main-portal/dist`（旧构建备份在 `backups/dist-20261016-1200`），其他部署点需自行重新构建前端才能显示 1.5.5 与新的内置更新记录。

## Known Release Risks

- 本次未变更依赖，未重跑 `npm audit`；`v1.5.3` 记录的前端 `echarts` / `vue-echarts` 依赖链 2 个 moderate 告警仍未处理。
- 会话预检依赖后端 `GET /api/v2/auth/verify` 可用；后端不可达或超时时按放行处理，认证判定退回到 API 层 401，属于有意的可用性取舍。
- 访客短路的判据是「本地既无访问令牌也无刷新令牌」；只剩刷新令牌的会话仍会发出请求（走刷新或换取 401），行为与 1.5.4 一致。
- `stores/auth.ts` 的 `restoreAuthData()` 对未知格式 token 仍无条件放行（本版未改动，避免影响后端 opaque token 支持），该口子由守卫侧的会话预检兜住。
- 两端的 ESLint 工具链当前不可用（缺少 `@typescript-eslint/recommended` 与 `@rushstack/eslint-patch`），本版本门禁为两端类型检查、测试与前端构建，lint 未纳入。
- 本机 8002 上运行的是 tsx 直跑源码的非生产实例（启动日志 `"isProduction":false`，PM2 侧 `NODE_ENV` 为 `development`），接口探测与浏览器实测证明了契约可用，但生产模式下的匿名开关判定与 mock 令牌拒绝未在本机复跑。
