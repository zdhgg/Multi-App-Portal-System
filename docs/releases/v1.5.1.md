# v1.5.1 - 应用启动生命周期与状态确认补丁

发布日期：2026-08-19

## Highlights

- 应用启动改为异步生命周期任务，接口快速返回任务 ID，前端继续确认最终结果。
- 慢启动、失败启动、临时状态查询失败和页面刷新场景都保留可恢复的状态信息。
- 同一应用的重复启动请求复用活动任务，避免并发拉起多个进程。
- PM2 启动在真实进程状态确认完成前保持“启动中”，修复状态确认窗口内重复点击的问题。

## API Changes

- `PUT /api/v2/applications/:id/start`
  - 返回 HTTP `202 Accepted`。
  - `data` 返回生命周期任务对象，状态为 `queued` 或 `running` 时表示请求已受理。
  - 重复请求返回同一个任务 ID，并通过 `data.reused = true` 标识。
- `GET /api/v2/applications/lifecycle-operations/:operationId`
  - 查询任务最终状态和结构化失败信息。
- `GET /api/v2/applications/:id/lifecycle-operation`
  - 查询指定应用最近一次启动任务，用于页面刷新和轮询超时后的状态核对。

## Compatibility

- 停止应用、PM2 管理和遗留 `/api/apps` 路由保持不变。
- 直接调用启动接口的客户端需要适配 `202` 响应和生命周期任务轮询，不应再假设请求返回时应用已经在线。
- 生命周期任务当前保存在 API 进程内存中；API 进程重启后，客户端应通过应用实际状态重新核对启动结果。
