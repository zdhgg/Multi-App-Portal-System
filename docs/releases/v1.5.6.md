# v1.5.6 - 管理页直达应用与运行优先排序

发布日期：2026-10-17

## Highlights

- 应用管理页里，已启动应用的名称现在是可点击链接：点一下就在新标签页打开该应用，不必再先到门户首页或自己拼端口地址。离线应用名保持普通文本，悬停时说明「应用未运行，启动后可点击名称访问」。
- 打开的端口按运行模式选择：开发模式用前端端口（Vite dev server），PM2 生产模式用后端端口（后端提供前端资源与 API）；地址跟随访问门户时使用的主机名，因此从局域网访问门户时点开也是同一台机器的地址。
- 应用管理页把已启动（含启动中）的应用排在列表前列，组内保持后端返回顺序，与门户首页「运行中优先」的排序规则一致。

## Added

- 访问地址解析模块 `main-portal/src/utils/appAccess.ts`：`resolveAppOpenPort()` 按全栈标记与运行模式选择端口（`deploymentMode` 缺失时用 `pm2ProcessName` 兜底判为生产模式），`resolveAppOpenUrl()` 生成访问地址（协议取自应用网络配置，访问路径取自 `accessPath`/`access_path`），`isAppOnline()`/`isAppOpenable()` 供界面判定名称是否可点击。
- 前端回归测试 `main-portal/src/tests/app-access-url.test.ts`（13 项）：生产/开发/未知模式的端口选择、PM2 进程名兜底、非全栈应用不受运行模式影响、单端口应用、无端口应用、访问路径拼接、https 协议、可打开判定。

## Changed

- 应用列表数据映射（`services/appsApi.ts`）：补齐 `deploymentMode`、`pm2ProcessName`、`isFullStack`、`accessPath` 四个字段。此前这些字段已经由 `GET /api/v2/applications` 返回，但在 DTO 转前端应用对象时被丢弃，导致无法判断该打开哪个端口。
- 应用名单元格（`views/Management.vue`）：在线且可解析出访问地址时渲染为可点击链接（蓝色文字、悬停出现外链图标与提示），点击调用 `resolveAppOpenUrl()` 后 `window.open(url, '_blank')`；离线或地址不可用时保持普通文本并给出说明性悬停提示。
- 应用列表排序（`views/Management.vue`）：`applyFilters()` 末尾增加稳定排序，`isAppActive()`（在线、启动中或 `isRunning`）的排在前面；搜索、状态筛选与 WebSocket 状态推送共用这一入口，启动应用后该行会立即上浮。
- 将根项目、前端、后端、系统配置、锁文件和前端内置更新记录版本统一提升到 `1.5.6`。

## Fixed

- 修复应用管理页无法直达运行中应用的问题：现在点击在线应用名称即可打开，端口的运行模式判定与门户首页一致。
- 修复应用接口返回的运行模式、PM2 进程名、全栈标记与访问路径在数据映射时丢失的问题。

## Compatibility

- 无后端接口变更，本次为纯前端改动，API 服务无需重启。
- 行为变化：管理页应用名在应用在线时呈现为可点击链接；列表顺序变为已启动的应用在前（组内顺序不变），启动/停止应用时该行会移动到对应分组。
- `dist/` 不入库：本机已重新构建 `main-portal/dist`（旧构建备份在 `backups/dist-20261017-1738`），其他部署点需自行重新构建前端才能显示 1.5.6 与新的内置更新记录。

## Known Release Risks

- 端口判定依赖后端持久化的 `deploymentMode`；该字段为 `unknown` 且应用在线时，用 `pm2ProcessName` 兜底判为生产模式（开发模式启动会清空该字段，因此非空即视为 PM2 托管）。若某应用既无运行模式记录、又非 PM2 托管、却确实在后端端口提供服务，会被打开前端端口——这与门户首页既有的取舍一致。
- `pm2ProcessName` 兜底只影响全栈应用的端口选择；非全栈应用始终使用前端/主端口。
- 管理页排序在状态推送时实时生效：启动/停止应用会让对应行移动分组，批量勾选过程中可能遇到行位移。
- 生产构建（`import.meta.env.PROD`）会拒绝 `mock-jwt-token-*` 令牌，因此管理页的点击行为在开发服务器上验证，生产产物只做了产物内含版本/更新记录与访客首页的核对。
- 两端的 ESLint 工具链当前不可用（缺少 `@typescript-eslint/recommended` 与 `@rushstack/eslint-patch`），本版本门禁为两端类型检查、两端测试与前端构建，lint 未纳入。
- 本次未变更依赖，未重跑 `npm audit`；`v1.5.3` 记录的前端 `echarts` / `vue-echarts` 依赖链 2 个 moderate 告警仍未处理。
- 本机 8002 上运行的是 tsx 直跑源码的非生产实例（启动日志 `"isProduction":false`，PM2 侧 `NODE_ENV` 为 `development`），生产模式下的匿名开关判定与 mock 令牌拒绝未在本机复跑。
