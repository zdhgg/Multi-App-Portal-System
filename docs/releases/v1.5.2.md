# v1.5.2 - 控制台窗口与日志噪声修复

发布日期：2026-09-27

## Highlights

- 修复 Windows 上执行 PM2 诊断、端口状态清理或 PM2 状态保存时会闪出控制台黑框的问题，共 11 处子进程调用补齐 `windowsHide`。
- 全栈探测日志按目录去重：周期性状态同步不再每 30 秒重复输出同一批日志（历史日志中该条信息约占 90% 的体量）。
- 新增门户看门狗与隐藏启动包装，后端或 PM2 守护进程异常退出后可自动恢复，且不再弹出控制台窗口。
- 新增子进程窗口审计脚本，用于检查所有子进程调用是否隐藏窗口，可作为提交前检查或 CI 门禁。

## Added

- `scripts/monitoring/portal-watchdog.ps1`
  - 每 5 分钟检查 PM2 守护进程与 `portal-api`（端口 8002）。
  - 守护进程缺失时执行 `pm2 resurrect`，失败则 `pm2 start ecosystem.config.js`；应用不在线时执行 `pm2 restart` / `pm2 start`；进程在线但端口连续两个周期未监听时强制重启。
  - 每次运行的结论写入 `logs/watchdog-last-run.txt`（覆盖式，不增长），实际动作写入 `logs/watchdog.log`（超过 5MB 自行轮转）。
  - 维护模式：存在 `logs/WATCHDOG_PAUSED` 文件时跳过本轮自愈。
- `scripts/monitoring/run-watchdog-hidden.vbs`
  - 经 `wscript` 以 `SW_HIDE` 启动看门狗，避免计划任务每次运行时闪出控制台窗口。
  - 等待子进程结束后再退出，使任务状态真实反映运行时长，配合 `MultipleInstances=IgnoreNew` 避免重叠执行。
- `scripts/diagnostics/audit-spawn-windows-hide.cjs`
  - 扫描 `detection-api/src` 下全部子进程调用点，报告缺失 `windowsHide` 的位置与其中处于周期性循环内的调用。
  - 退出码 0 表示无漏网，1 表示存在漏网，可直接用于提交前检查或 CI。

## Changed

- 全栈探测日志改为按目录去重：`detection-api/src/core/ApplicationService.ts` 只在探测结果发生变化时输出 `Detected fullstack project`。
  - 背景：PM2 状态同步每 30 秒会重新解析全部应用，此前每轮都重复输出同一条 info 日志；在 1.35GB 的历史日志中，该条信息占 407 万行里的约 367 万行。
- 将根项目、前端、后端、系统配置、锁文件和前端内置更新记录版本统一提升到 `1.5.2`。

## Fixed

- 修复 Windows 上以下 11 处子进程调用缺少 `windowsHide`、会闪出控制台窗口的问题：
  - `detection-api/src/services/pm2Service.ts`：`pm2 save` / `pm2 resurrect` 的 `exec` 兜底分支。
  - `detection-api/src/scripts/portStateCleanup.ts`：`tasklist`、`netstat`、`kill -0`、`lsof`。
  - `detection-api/src/services/pm2DiagnosticService.ts`：自动修复命令、`netstat`、`pm2 logs`。
  - `detection-api/src/utils/portCleaner.ts`：`lsof`、`kill -9`。
- 保留 `detection-api/src/routes/configurationExport.ts` 的 `windowsHide: false`：该处启动的是面向用户的离线还原助手窗口，必须保持可见。审计脚本将其登记为有意豁免。

## Compatibility

- 无接口变更，行为与 `1.5.1` 兼容。
- 新增脚本仅依赖 Windows 自带的 PowerShell 7、`wscript` 与 Node.js，不引入新的运行时依赖。
- 看门狗会主动拉起 `portal-api`，因此手动 `pm2 stop` 会在下一个周期被恢复；需要停机维护时请创建 `logs/WATCHDOG_PAUSED` 或停用计划任务 `PortalSystem-Watchdog`。

## Known Release Risks

- 本次未变更任何依赖，因此未重跑 `npm audit`；`v1.5.1` 记录的审计结果（根项目与后端 0 vulnerabilities、前端 0 high / 2 moderate）截至本次发布未重新确认。
- 前端仍有 `echarts` / `vue-echarts` 依赖链产生的 2 个 moderate 告警，与 `v1.5.1` 相同，需单独安排大版本兼容升级。
- 看门狗的自动化验证是在开发机上以手工触发计划任务的方式完成的，未覆盖"计划任务在长时间无人值守下持续运行"的场景。
- 日志归档（`detection-api/logs/archives/*.gz`）与 PM2 版本升级属于本机运维动作，不随本次版本发布分发。
