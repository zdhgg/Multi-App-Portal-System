# v1.5.4 - 慢启动可靠性与启动阶段诊断

发布日期：2026-10-16

## Highlights

- 全栈应用慢启动不再被误杀：子进程端口就绪等待默认 90 秒 → 180 秒，并按子进程各自的就绪截止时间放宽健康检查宽限。
- 新增启动阶段诊断：`startup_phase` 日志串起「命令发出 → 首条输出 → Nest 初始化 → 端口等待 → 结果」，超过 30 秒的启动每 15 秒采样一次进程树资源，慢启动有了可复盘的证据。
- 离开管理页面不再把正在观察的启动任务当成失败：取消只作用于本页观察，重新进入页面继续沿用服务端任务。
- 已登录用户的公开接口请求始终携带凭证，匿名开关配置漂移不再让管理员在首页拿到 401。

## Added

- 启动诊断（`detection-api/src/core/startupDiagnostics.ts`）
  - `startup_phase` 日志字段：`attemptId`、`processId`、`pid`、`phase`、`elapsedMs`，覆盖 `spawn_requested`、`first_output`、`nest_bootstrap`、`nest_ready`、`port_wait_started`、`port_ready`、`port_timeout`、`exited_before_ready`、`exited`、`spawn_error`、`tracking_removed`。
  - 超过 30 秒的启动每 15 秒采样一次 Windows 进程树：累计 CPU 时间与工作集、系统 CPU、可用内存、读页/写页、磁盘活动；不记录命令行与环境变量；采样 PowerShell 隐藏窗口、最多 10 秒；计数器不可用时仍记录内存并标记 `resourceSampleStatus: partial`。
  - 就绪、退出、错误或取消跟踪后停止采样，迟到结果不再写日志。
- 就绪超时可配置：`PORTAL_STARTUP_TIMEOUT_MS` 支持应用进程 `environmentVariables` 与 Portal 服务环境变量两级，应用配置优先；接受 10000–240000 毫秒的有限数字，非法值回落 180000。
- 前端回归测试 `main-portal/src/tests/public-api-auth-header.test.ts`（4 项）：匿名模式下仍携带凭证、无会话保持匿名请求、关闭匿名模式行为不变、仅无会话时才判定为游客受限。

## Changed

- 全栈子进程端口就绪等待默认 90 秒 → 180 秒；管理页面五分钟的观察窗口与轮询策略不变。
- 端口健康检查宽限跟随各子进程的就绪截止时间，端口就绪后立刻恢复常规检查；单进程应用仍为从启动起 120 秒。
- 前端启动观察（`Management.vue`、`types/lifecycleOperation.ts`）：取消只表示「本页不再观察」，重新进入页面按服务端任务继续确认；请求返回后再次检查页面是否已退出，迟到结果不落地；仅本地取消忽略 `AbortError`。
- 公开接口请求配置（`services/publicApi.ts`）：`requireAuth` 改为只取决于是否存在本地会话，匿名开关不再参与。
- 匿名浏览配置对齐：`configs/production.env.template`、`configs/production.env`、`detection-api/.env.example` 的 `ENABLE_V2_PUBLIC_ANONYMOUS` 统一为 `true`，并在模板中补充该开关与 `PORTAL_STARTUP_TIMEOUT_MS` 的说明。
- 将根项目、前端、后端、系统配置、锁文件和前端内置更新记录版本统一提升到 `1.5.4`。

## Fixed

- 修复匿名模式开启时已登录用户的公开接口请求不带 `Authorization`、管理员同样返回 401 的问题。
- 修复离开管理页面时启动任务被抛成 `AbortError` 并显示为启动失败、迟到响应更新已卸载页面的问题。
- 修复慢启动进程在就绪等待结束前健康检查宽限已到期、被健康检查误杀的问题。

## Compatibility

- 无后端接口变更；`/api/v2/public/*` 的鉴权范围未放宽，`ENABLE_V2_PUBLIC_ANONYMOUS=false` 时仍需认证。
- 行为变化：全栈子进程默认就绪等待 90 → 180 秒，「进程存活但端口未监听」的失败检出会相应延后约 60–90 秒；需要快速失败时把 `PORTAL_STARTUP_TIMEOUT_MS` 收紧到 10000–240000 区间内的值。
- 单进程应用不受就绪等待与宽限变更影响。
- `dist/` 不入库：本机已重新构建 `main-portal/dist`（旧构建备份在 `backups/dist-2026*`），其他部署点需自行重新构建前端才能显示 1.5.4。
- 匿名浏览需两端一致：后端 `ENABLE_V2_PUBLIC_ANONYMOUS` 与前端 `VITE_PUBLIC_API_ANONYMOUS` 只关一端会让游客拿到 401。

## Known Release Risks

- 本次未变更依赖，未重跑 `npm audit`；`v1.5.3` 记录的前端 `echarts` / `vue-echarts` 依赖链 2 个 moderate 告警仍未处理。
- 就绪等待延长意味着故障检出变慢，属于有意的可靠性取舍；对启动失败敏感的部署应显式收紧 `PORTAL_STARTUP_TIMEOUT_MS`。
- 启动诊断依赖 Windows PowerShell 计数器（`Get-CimInstance`），计数器不可用时降级为 `partial`，不影响启动判定。
- 匿名浏览行为依赖后端公开路由保持只读，后续新增公开接口时需复核鉴权范围。
- 两端的 ESLint 工具链当前不可用（缺少 `@typescript-eslint/recommended` 与 `@rushstack/eslint-patch`），本版本门禁为两端类型检查、测试与前端构建，lint 未纳入。
- 完整浏览器点击/路由切换验收与真实系统冷启动仍需现场验证（`docs/startup-reliability.md` 已注明）。
