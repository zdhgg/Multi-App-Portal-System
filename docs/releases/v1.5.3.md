# v1.5.3 - 会话保持与端口归属判定优化

发布日期：2026-10-01

## Highlights

- 网络抖动不再误登出：刷新令牌失败区分「后端明确拒绝」与「临时故障」，仅前者清除会话。
- 页面刷新时过期的访问令牌自动通过刷新令牌续期，充分利用后端 7 天刷新令牌有效期，不再因「过期超过 1 小时」直接清除会话。
- 端口归属判定在进程树不可用（查询超时或返回空列表）时降级为「无法核验」并附警告，不再误报「PID 不匹配」。
- 生产环境前端开启匿名公共 API：游客可浏览公开应用只读列表，管理操作仍需登录。

## Changed

- 前端认证（`main-portal/src/stores/auth.ts`、`TokenRefreshManager.ts`、`services/api.ts`、`utils/routeGuards.ts`）
  - 刷新令牌失败按错误类型分类：`ApiError(401)`（后端明确拒绝）清除会话；网络、超时等临时故障保留会话。
  - 新增 `isSessionRetainedAfterRefreshFailure()` 作为单一判定点，API 层与路由守卫共享，不再各自反推刷新令牌状态。
  - 会话恢复（`restoreAuthData`）：访问令牌过期时先经 `restoreSessionViaRefreshToken` 续期，返回 `refreshed` / `rejected` / `transient` 三态；临时故障同样保留会话。
  - 并发轮换恢复：刷新令牌被其他标签页的刷新轮换撤销（401）时，重新读取存储中的最新令牌重试一次。
  - 路由守卫在刷新临时失败时放行本次导航，真正的认证失效由 API 层 401 兜底处理。
- 端口归属判定（`detection-api/src/services/PortInventoryService.ts`）
  - `ProcessDetails` 新增 `treeAvailable` / `treeWarning`：进程树查询被超时中止（按 killed 标记识别）或解析为空时视为不可用。
  - 依赖父子关系的归属判定在降级态返回 `unverified` 并在快照中携带警告文案；警告随 2 秒进程详情缓存重放，避免相邻快照质量来回跳动。
  - 不依赖进程树的判定保持严格：应用不在运行态、监听 PID 属于其他受管应用的根进程，仍报 `mismatch`。
  - 超时错误文案压缩空白并截断至 120 字符，便于在警告列直接阅读。
- 配置
  - 两份 `system-config.json` 的 `allowedBasePaths` 新增 `D:\APP`。
  - `main-portal/.env.production` 将 `VITE_PUBLIC_API_ANONYMOUS` 置为 `true`，允许游客匿名访问公开只读接口。
- 将根项目、前端、后端、系统配置、锁文件和前端内置更新记录版本统一提升到 `1.5.3`。

## Fixed

- 修复网络抖动导致误登出的问题：此前任何刷新失败都会清除本地会话并要求重新登录。
- 修复访问令牌过期超过 1 小时的会话在页面刷新后被直接清除、未利用刷新令牌续期的问题。
- 修复进程列表查询被超时中止时错误信息为空、难以定位原因的问题。

## Compatibility

- 无后端接口变更。
- 前端行为变化：刷新临时失败不再触发登出与「登录已过期」提示，改为保留会话继续请求；依赖「任何刷新失败即登出」的自动化场景需重新评估。
- 匿名公共 API 仅覆盖公开只读接口，后端鉴权未放宽；不希望游客浏览时将 `VITE_PUBLIC_API_ANONYMOUS` 改回 `false` 并重新构建前端即可。
- `dist/` 不入库：部署本版本时需重新构建前端（`npm --prefix main-portal run build:check` 或 `build`）。

## Known Release Risks

- 本次未变更任何依赖，因此未重跑 `npm audit`；`v1.5.1` 记录的审计结果（根项目与后端 0 vulnerabilities、前端 0 high / 2 moderate）截至本次发布未重新确认。
- 前端仍有 `echarts` / `vue-echarts` 依赖链产生的 2 个 moderate 告警，与 `v1.5.1` 相同，需单独安排大版本兼容升级。
- 会话保留策略属于安全相关行为变更：被 suspension/共享设备的部署若依赖「刷新失败立即登出」，需评估后另行收紧。
- 匿名浏览行为依赖后端公开路由保持只读；后续新增公开接口时需复核鉴权范围。
