# v1.5.0 - 统一端口清单与运行态可靠性升级

发布日期：2026-08-15

## Highlights

- 新增统一端口清单，容量统计、监听列表、归属核验和冲突提示共享同一份系统快照。
- 端口监控明确展示数据新鲜度和实时连接状态，刷新失败时保留最后成功快照，不再回退到伪造统计值。
- 强制释放重新核验当前 PID，失效分配改为管理员先预览、再确认执行，系统与门户保留端口禁止直接释放。
- 全栈应用启动会等待前后端端口真正就绪；任一子进程失败时自动清理部分启动结果。
- 应用启动与端口冲突流程新增运行态恢复，避免旧离线数据覆盖已经成功启动的应用。

## Included Work

- `PortInventoryService` 聚合端口配置、应用配置、直启进程、PM2 进程、系统监听和保留端口信息。
- 新增 `/api/v2/config/ports/inventory`，原有统计、扫描状态和冲突接口继续保留，并从统一清单生成兼容响应。
- 端口归属区分 `verified`、`mismatch`、`duplicate-config`、`unmanaged`、`unverified` 和 `reserved`。
- 端口页面和 Pinia store 改为统一快照驱动，支持原子更新、并发请求版本控制、过期数据保留和轮询降级。
- WebSocket 支持 `port_inventory_invalidated` 轻量通知，并兼容新 `payload` 与旧 `data` 消息格式。
- 强制释放要求 `snapshotId` 与 `expectedPid`，执行前重新扫描监听进程并阻止 PID 变化后的误释放。
- 清理失效分配新增 GET 预览接口，门户只向管理员显示清理与配置操作。
- Windows 端口快照限定为 TCP LISTENING，Linux/macOS 补充 `ss` 与 `netstat` 监听解析。
- 全栈后端优先选择 `dev:watch`，启动阶段等待所有子进程端口就绪，失败时停止整个进程组。
- 应用管理在启动完成和端口冲突后同步实际运行态，避免延迟响应造成错误的离线或失败提示。

## Compatibility

- 配套门户已经适配新的统一端口清单和安全释放参数。
- 直接调用强制释放接口的客户端必须传入当前清单的 `snapshotId` 与被观察到的 `expectedPid`。
- 原有端口统计、后台扫描状态、冲突检测和清理 POST 路由继续保留。
